## 〇、统一中间表示（IR）

所有阶段读写同一种 JSON 结构（`ledger` 系），保证"阶段间只用文件交接、每阶段可单独重跑"：

```jsonc
{
  "schema_version": 1,
  "meta": {
    "sources": [                                 // 每个输入文件一条（审计凭证：原始件指纹）
      {"file": "wechat-demo-01.csv", "platform": "wechat",
       "sha256": "<原始字节手印>", "bytes": 12345,
       "encoding": "utf-8-sig",                  // 实际采用的解码通道（显式记录）
       "rows_total": 42, "rows_ok": 40, "rows_invalid": 1, "rows_unknown": 1}
    ],
    "params_digest": "<规则包文件 sha256 聚合>"   // 结论可复现性的锚点
  },
  "records": [
    {"id": "wechat-demo-01.csv:3",               // 源文件 + 源行号确定性派生
     "source_platform": "wechat", "source_file": "wechat-demo-01.csv", "source_row": 3,
     "time": "2026-09-01 12:00:00",              // 规范化为本地时间字符串（无时区换算）
     "amount": "12.34",                          // Decimal 字符串化（正数）
     "direction": "expense|income|neutral",      // 收/支/不计收支
     "counterparty": "示例便利店甲",              // 原始写法
     "description": "扫码支付",
     "raw_fields": {"交易类型": "...", "...": "..."},  // 原始行原样字段（可审计）
     "row_status": "ok"}
  ],
  "issues": [                                    // 行级问题（清单化，绝不静默）
    {"source_file": "wechat-demo-01.csv", "source_row": 5,
     "kind": "invalid|unknown", "code": "amount_not_numeric", "detail": "..."}
  ],
  "file_issues": [                               // 文件级问题（整份不可用，不进行级清单）
    {"file": "bank-demo-bad.csv", "code": "header_not_found", "detail": "..."}
  ]
}
```

- **id 稳定**：同一输入两次运行，id 完全一致（文件标识 + 行号派生，不依赖运行顺序）。
- **三态**：`ok` / `invalid`（行不合格，不入 records，进 issues）/ `unknown`（行可解析但有字段未登记，入 records 且显式标注）。三态矩阵必须落测试（模块① DoD）。
- **原始不可变**：各阶段**只增不改**——normailze/dedup/classify 的产物都是"上一阶段产物 + 新增字段/新增段"，不改写既有字段值；原始行数据（`raw_fields`）从入库起终身保留。

## 一、模块① 多平台账单导入（ingest）

**输入**：用户官方自助导出的账单文件——微信（解密后 CSV/XLSX）、支付宝（CSV）、银行（CSV+XLSX，首期仅此两种）。
**输出**：`ledger.json`（IR）+ 行级/文件级问题清单。
**命令**：`brc import <文件...> --out output/ledger.json`（M2 实现）。

### 1.1 编码探测（显式白名单 + 显式顺序）

探测顺序（**写死、文档化、测试锁定**）：

1. **BOM 探测**：UTF-8 BOM（`utf-8-sig`）、UTF-16 LE/BE（`utf-16`）→ 命中即用；
2. **UTF-8 严格**解码尝试（含纯 ASCII）；
3. **GB18030** 解码尝试（GBK 的超集，覆盖 GBK 导出）；
4. 全部失败 → **文件级 `invalid`**（`code=encoding_undetermined`），报错退出码 2，**不猜测**。

要点：第 2 步必须**先于**第 3 步——UTF-8 中文文本的字节串在 GB18030 下也几乎总能"解码成功"（产出一堆乱码），顺序反了会把正常 UTF-8 文件译成乱码且**不报错**。

### 1.2 表头定位（支付宝等"表头广告行"剥离）

- 支付宝官方导出文件**顶部若干行是平台说明文字**（非表头）。规则：从前 N 行（N 为写死上限）中**定位第一行满足"预期列名命中数 ≥ K"**的行作为表头（预期列名集与 K 来自规则包 `data/rules/`，非代码内联）。
- 定位失败 → **文件级 `invalid`**（`code=header_not_found`），报错并列出尝试过的候选行，**不猜测**。
- 表头行以上内容记入 `meta.sources[].header_skipped_lines`（可审计）。

### 1.3 列名漂移（别名映射）

- 列名按**列名白名单 + 别名映射表**（冻结规则包）映射到规范字段：交易时间 / 金额 / 收支类型 / 对手方 / 商品说明 / 交易状态 等。
- **未登记列名** → 该列记 `unknown`（行仍可用，`raw_fields` 保留原值；累计出现在 issues 汇总中，便于发现新版导出列）。
- **必填字段**（交易时间、金额、对手方）任一列映射失败 → 文件级 `invalid`（`code=required_column_missing`）。
- 别名映射表与"表头定位预期列名集"共用同一份规则包数据（单一来源）。

### 1.4 行级解析与三态

- 金额：去千分位（`,`）、去货币符号（`¥ ￥ $` 等白名单）、收支分列（收入列/支出列 vs 单列带正负号 vs 收支类型列）按显式规则归一为 `amount`（正数 Decimal 字符串）+ `direction`（expense/income/neutral）；
- 非数值、金额为空、时间不可解析、**列对齐不可信**（字段数与表头不匹配）→ 行级 `invalid` 入 issues，**不入库**（宁可少一行，不可把错位的值当对的）；
- `neutral`（"不计收支"）**不是异常**：保留入库（它是转账语义的重要证据），只标记方向；
- `unknown` 行：可解析但出现未登记列名/未登记收支取值 → 入库并在 issues 中显式列出（`kind=unknown`）。

### 1.5 确定性纪律

- 解析**规则优先、全程确定**（无启发式打分、无模糊匹配）；
- 输出排序：records 按 `(source_file, source_row)`；issues 按 `(file, row, code)`；
- 异常清单**全部打印**（不截断）；每个输入文件的 sha256/字节数入 `meta`（审计凭证）。

## 二、模块② 商户名归一化（normalize）

**输入**：IR 的 `counterparty` 字段。**输出**：归一化名称 + 归并台账（逐条依据）。**命令**：`brc normalize --ledger ... --out ...`（M3）。

### 2.1 规则归并（确定、可观测）

归并动作序列（顺序写死）：

1. 去除首尾及内部**空白字符**（全角空格、制表符等）；
2. **全角/半角统一**（ASCII 范围的全角转半角，等等价映射表）；
3. **后缀剥离**（"有限公司 / 有限责任公司 / （有限）"等白名单后缀，剥离后非空才生效）；
4. **别名表命中**（冻结产物，原名 → 规范名）；
5. 未命中任何规则 → **原样保留**（不猜测、不做相似度）。

- **不做模糊语义猜测**：编辑距离、分词、读音相似度一律不引入（首期）。
- **逐条可观测**：每个发生变化的名称挂依据——`{"rule": "suffix_strip|fullwidth_norm|alias_table", "detail": "...", "evidence": "<命中条目 id>"}`；未命中的原样保留且依据为空（显式区分"归并了"与"没归并"）。
- **动作顺序实现澄清（M3 定稿）**：别名表命中在**全半角归一之后**进行——别名 variants 先过同一归一管线（去空白→全半角→后缀剥离）再建索引，保证"表中写法"与"流水写法"在同一口径下比较（否则全角括号写法的变体永远匹配不上）。去空白 = 移除首尾**及内部**全部空白字符。

### 2.2 冻结与守门

- 别名表与后缀白名单是**程序化生成的冻结产物**（`data/rules/aliases.json` + 位级守门 `--check`，禁手改）——"引擎对不对"必须能与"数据对不对"分离；
- 同一原名在任何上下文归一结果恒定（归一化是纯函数）。

## 三、模块③ 跨平台去重（dedup）

**输入**：归一化后的 IR。**输出**：候选簇清单（成员、依据、代表笔）+ 净流水视图。**命令**：`brc dedup --ledger ... --window-seconds N --out ...`（M3）。

### 3.1 判定键（三元组）

- **金额相等**（Decimal 精确相等）+ **时间窗口**（|Δt| ≤ W 秒）+ **对手方相等**（②归一化后的名称）；
- **时间窗口 W 为用户可配置参数**：默认值来自规则包（经验默认，**标注"非官方"**）；CLI 可覆盖（`--window-seconds`），实际生效值记录进产物与报告。

### 3.2 聚类规则（确定、同输入同划分）

- 对**同一方向**（expense / income / neutral 各自独立）的流水做候选聚类——"同一笔"必然同方向；
- 按固定排序（时间 → 平台 → 来源行号）线性扫，窗口内 + 三元组相等的记录归入同一候选簇（**链式相邻聚类**，闭区间判定 `|Δt| ≤ W`）；
- 簇划分无随机性；簇排序、成员排序规则显式（全部写测试）。

### 3.3 "看起来像重复" ≠ "判定为重复"（逐簇依据）

- 三元组命中只记**候选簇**；是否合并必须再过**跨平台前提**：
  - 候选簇内包含 **≥2 个不同平台** → 判定为**跨平台重复**（`verdict=duplicate_cross_platform`）；
  - **同平台**同金额同时刻的候选 → **默认不合并**，标 `verdict=candidate_same_platform`（显式可见，需人工复核；绝不静默合并也绝不静默忽略）；
- 每个判定挂依据（簇内成员、平台集合、Δt 实测值）；
- **去重不改变原始流水**：净流水是"原始流水 + 去重标记"的**视图**；每簇选**代表笔**（排序规则：时间最早 → 平台优先级（参数包定义）→ 来源行号，写死并测试），代表笔计入净支出，其余成员标 `duplicate` 排除出净额。

### 3.4 边界与测试要点（M3/M4）

- 窗口边界：**恰好 `Δt = W`** 必须命中（`≤` 闭区间），`W+1s` 不命中——边界用例直接构造（规则驱动，不依赖真值库采样）；
- **防误报**：金额相同但时间超窗、时间在窗但对手方不同、对手方相同但金额差 1 分——各配反例测试；
- 簇内多平台链式传播（A-B 近、B-C 近、A-C 远）的划分结果按规则固定，写测试。

## 四、模块④ 转账/退款/AA回款语义识别（classify）

**输入**：归一化后的 IR（对手方、商品说明、收支方向）。**输出**：逐行语义标签 + 判定依据。**命令**：`brc classify --ledger ... --out ...`（M3）。

### 4.1 标签集与判定方式

标签集：`消费 / 本人转账 / 退款 / AA回款 / 报销 / 未知`。

- **判定 = 词面命中 + 收支方向组合**（冻结关键词表的规则条目：`{id, label, direction_condition, keywords[], priority}`），**不做自由文本语义硬判**；
- 规则按固定优先级顺序评估（优先级数值来自规则包）；同一行命中多条 → 按优先级取首个，**依据记录全部命中条目**（可审计）；**同优先级按规则 id 升序**（评估序完全确定，M3 定稿）；
- **"消费"白名单按商户类分列多条规则**（零售/出行/充值/订阅各一条，同 priority 同 label）——命中来源规则可区分（M3 定稿，订阅类商户由 v3 规则包补登记）；
- **"未知"是一等结论**：未命中任何规则 → `未知`，在报告与清单中**显式列出**；
- **绝不把"未知"静默当作"消费"**（那会让"真实支出"虚高）——"消费"本身也必须由正命中产生，**没有 fallthrough 默认**（"消费"的正命中来源在 M3 定稿：方向条件 + 商户类词表/结构条件，同样落进冻结规则包）。

### 4.2 词表纪律

- 关键词表是**冻结产物**（`data/rules/keywords.json`，程序化生成 + 位级守门 + 禁手改）；
- **一处定义、多处引用**：识别引擎、报告、基准全部引用同一份（经 `params.py` 唯一访问点）；严禁在解析/报告层出现第二份词表（会漂移出"假未知/假消费"）。

### 4.3 与"真实支出"的关系（报告口径）

- **真实支出主口径 = 已判定为`消费`的支出净额 − 已判定为`退款`的入账**（计算实现见 M3/M4，报告只呈现结论不重算）；
- `本人转账 / AA回款 / 报销` 不计入支出侧；
- **`未知` 单列**：报告中给出未知行清单 + 合计金额，并诚实标注"若全部计入支出，上限为 X"——主口径不把未知混入，也不假装未知不存在。

## 五、模块⑤ 周期性订阅识别与报告（report）

**命令**：`brc report --ledger ... --out-dir output/`（M4）。

### 5.1 订阅识别（确定性）

- 判定 = **商户 + 金额 + 日期间隔**的规则判定：同商户（归一化后）、同金额、相邻间隔落在周期容差内、重复次数 ≥ 最小重复次数，判为周期（月/季/年，参数化周期表）；
- 参数（最小重复次数、间隔容差、涨价判定阈值）**用户可配置**、默认值来自规则包（经验默认，非官方）；
- **涨价追踪只输出观测到的变动**（前后金额 + 日期），不做任何"预测"类输出；
- 周期中断（漏一期）、金额变化是否续判同一订阅：规则写死并测试（M4 定稿）。

### 5.2 报告（单文件 HTML + 机读 JSON 双轨）

- **单一渲染源**：`report/sections.py` 产出结构化章节 → HTML 渲染器与 JSON 渲染器各自消费（"两格式内容一致"是**结构性质**，非人工比对）；
- 章节（草案，M4 定稿）：
  1. 概览（笔数、三平台分布、时间范围、`params_digest` 与版本）；
  2. **真实支出汇总**（口径说明 + 未知单列区间）；
  3. 去重簇明细（含 `candidate_same_platform` 显式分区）；
  4. 语义标签分布（`未知` 单列）；
  5. 订阅清单 + 涨价记录；
  6. 异常/未知清单（行级问题全量）；
  7. **参数来源块**（每项参数：值 + 来源（经验默认/用户覆盖）+ 规则包版本）；
  8. 隐私声明 + 免责声明。
- **硬性**：单文件内联（无 CDN/外链/遥测/外部字体）；断网可开；**同输入 → 同字节**（无时间戳、固定排序、固定数值格式），配位级守门测试；
- **报告只呈现引擎结论，不做二次计算**（避免第二份口径）。

## 七、参数与配置纪律（数值口径单点）

- 全部可配置数值（时间窗口、订阅最小重复次数、间隔容差、涨价阈值、平台优先级、表头定位 K 值……）**只在 `data/rules/` 定义**，规则包 manifest 记录每个参数的：值 / 单位 / 是否用户可配 / 来源标注（经验默认，非官方）/ 说明；
- 代码侧**唯一访问点** `params.py`（加载 + 校验 + 摘要计算）——引擎/报告/基准不得出现第二份数值；
- **零参数字面量门禁**（M3 落地）：从规则包**运行时**程序化生成禁用 token 集（`params.param_tokens`：params + bench_thresholds 数值，整数取十进制串、浮点取双形式；**一位数豁免**——结构性小整数如数组下标/循环基数不构成口径漂移风险，豁免理由逐条在案），扫描引擎/CLI/报告/基准源码（含 docstring/注释；注释行仅当含"例/如/默认"举例语气才豁免——防代码漂移不防注释漂移）；阳性对照走**tmp 注入式测试**（`tests/test_no_param_literals.py`：注入含 token 的文件 → 门禁必红，不污染工作树）；`selftest` 增设常驻门禁检查项；`params.py` 豁免自身（参数的家）。
- **CLI 覆盖记录**：用户命令行覆盖的参数，实际生效值必须进产物与报告的参数来源块（可审计）。

## 八、编码与跨环境纪律（本机/CI 双通道的工程约定）

- 程序入口（`cli.main` 与每个 `tools/` 脚本）先做**编码守卫** `_ensure_utf8_stdio()`：探测 `sys.stdout/stderr.encoding`，遇到非 UTF-8 且非中文控制台（cp936/GBK 系）的编码（如 cp1252）→ `reconfigure(encoding="utf-8")`；中文控制台保持不动；
- **子进程调用一律显式 `encoding="utf-8"`**（不依赖 locale 解码）；
- CI 全 job 设 `PYTHONUTF8=1` + `PYTHONDONTWRITEBYTECODE=1`；
- 测试里含"cp1252 下中文输出不崩"回归（本机即可跑，不等 CI）。

## 九、内置基准（bench）设计概要（M4 落地）

四个套件（覆盖声明随 manifest 双登记：**总数 / 采样数 / 清单**，显式声明"抽样覆盖非穷举"）：

- **B1 导入**：生成器真值 vs 解析结果，行级三态字段级 P/R/F1（目标 F1 ≥ 0.95 或按门槛表）；
- **B2 去重**：簇级判定对比真值（应合并/不应合并），准确率与误报数；
- **B3 语义**：逐行标签比对（含 `未知` 的"可区分性"：应未知的绝不能被猜成消费）；
- **B4 订阅/涨价**：周期与涨价记录比对；
- **规则驱动层**（不读真值库）：去重窗口/周期容差的**边界端点**直接构造断言（样本驱动证明"样本上对"，规则驱动证明"所有端点上对"）；
- **双向对账**：窗口边界的**公式推导端点 vs 粗扫+细扫穷举恢复**两条独立路径互验（B5 或并入 B2，M4 定稿）；
- **探活（可证伪）**：每套件注入一个缺陷（坏引用/坏期望/窗口拨错），基准必须报未达标且文本同步声明——"基准全绿"必须能被证伪；
- **门槛是数据**：达标线随规则包 manifest 下发（代码只读，缺失即配置错误退出 2）；
- **真值库语义**：只存输入与期望，**观测由基准运行时实算**（真值库出现 `observed` 类字段即门禁报红）；
- 退出码：0 达标 / 1 未达标 / 2 用例名或用法错误（`--only` 未知名必须 exit 2，不静默跳过）。

## 十、测试策略（贯穿）

- **每个解析器/规则器配生成器样例回归**（合成样例就是回归输入）；失败路径齐备：缺文件 / 坏编码 / 表头失败 / 空文件 / 数字列非数值 / 词表缺失；
- **守门要做变异验证**：新增或改写的守门测试，先故意弄坏被测行为 → 必须变红（假门排查）；
- **双解释器全量**：本机 3.8 与 3.12 各自全量跑；"本机能跑"≠"跨版本证据"，跨版本行为以 CI 为准（未接远端前标注"待首推验证"）；
- **测试面 = 安装面 = README 指令面**：测试真 import 的依赖必须在 README 安装行与 CI 安装行的 extras 集合内；README 让用户跑的每条命令（含 `tools/` 脚本）都要在上述通路里可跑（三面交叉检查由 M5 落地为守门）；
- 子进程测试**显式指定 encoding**；断言只锚"被测行为"（不把环境相关量写进硬门）。
