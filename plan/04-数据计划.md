# plan/04 数据计划

仓库 `10-16-bill-reconciler`（多平台账单"真实支出"对账器）。v1（2026-10-15，M0 计划先行阶段落盘）。

> **纪律来源**：合成数据规则、假商户白名单、真值台账纪律、数值口径单点、隐私红线——**权威文本是 `data/README.md`**（含三态说明与依据查证记录）。本文档是这些纪律在 M1（数据先行）的**实施计划**：资产清单、生成器方案、守门体系、台账格式、覆盖矩阵。

## 一、数据资产总览（三类，全部程序化自制）

本项目**没有外部数据源**（不联网获取任何数据）：全部数据资产由本仓库生成器程序化产出，零外部依赖、零 API。

| # | 资产 | 目录 | 内容 | 生成器 |
|---|---|---|---|---|
| A | **合成账单样例** | `data/samples/` | 三平台（微信/支付宝/银行）的账单文件，按形态矩阵刻意注入全部异常形态与语义形态 | `tools/gen_samples.py` |
| B | **真值台账** | `data/truth/` | 与样例**同源同一次运行**产出的标注：哪几笔应去重、每笔的期望标签、订阅/涨价期望、导入期望三态 | `tools/gen_samples.py`（同运行） |
| C | **冻结规则包** | `data/rules/` | 参数包（manifest）+ 语义关键词表 + 商户别名表 | `tools/gen_rules.py` |

统一守门入口：`tools/check_frozen.py`（重跑全部生成器 `--check`，逐字节比对，任一漂移即非零退出）。

## 二、生成器设计（确定性纪律）

- **自研确定性 RNG**（splitmix64，固定 seed）；**禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟**；产物**无时间戳**；
- 生成器自身版本号入产物头（改逻辑 → 版本号++ → 重生成全目录 → 提交）；
- **`--check` 模式**：重新生成到内存/临时区，与入库件**逐字节比对**，输出冻结态标记（如 `FROZEN_TRUTH_OK`）并以退出码携带结论；
- 生成 → 入库 → 之后**只增不改**；改需求 = 调生成器 + 整目录重生成 + 一并提交（配"再生成位级一致"守门测试，防"手改了入库件"）；
- XLSX 类样例：自写最小 writer 固定 `ZIP_STORED` + `create_system=0` + 固定 `date_time` 常量 + 条目排序 → **任意平台重生成位级一致**；
- 全部冻结文件在 `.gitattributes` 标 `-text`（防 EOL 改写字节）；台账登记每个文件的 sha256，克隆后可比对。

## 三、形态矩阵（注入清单，M1 定稿）

**覆盖度双登记**：manifest 逐形态登记「形态总数 / 采样数 / 清单」，显式声明"抽样覆盖、非穷举"。以下为草案清单，M1 定稿后与真值库 manifest 同步：

### 3.1 导入形态（对应 B1）

| 形态 | 注入要点 |
|---|---|
| 编码 | UTF-8 BOM / UTF-8 无 BOM / GBK / GB18030 / 故意坏编码（→ 文件级 invalid） |
| 表头广告行 | 支付宝式：表头前有 2~4 行说明文字（含不同行数与文案变体）；微信式：说明行 + 汇总行 |
| 列名漂移 | 同义列名变体（如"交易对方"/"交易对象"、"金额(元)"/"金额"）、含空格变体；未登记列名（→ unknown） |
| 金额写法 | 千分位 `1,234.56`、货币符号 `¥￥`、单列正负号、收支分列、收支类型列（含"不计收支"） |
| 行级异常 | 金额非数值 / 金额空 / 时间不可解析 / 列数不匹配（→ 行级 invalid，清单化） |
| 文件级异常 | 空文件 / 只有表头 / 缺必填列 / 坏编码（→ 文件级 invalid，exit 2 语义） |
| 平台文件类型 | 微信 CSV + XLSX、支付宝 CSV、银行 CSV + XLSX（各 ≥1 份） |

### 3.2 语义形态（对应 B3）

消费 / 本人转账（双方向）/ 退款 / AA回款 / 报销 / **未知**（必须注入：既不命中消费规则也不命中转账词表的流水）——各 ≥ 若干例，含中文关键词变体与**干扰例**（含关键词片段但方向条件不符 → 不得误判）。

### 3.3 去重形态（对应 B2）

跨平台重复簇（2 平台 / 3 平台各若干）；**窗口边界**（恰好 `Δt=W` 应合并、`W+1s` 不应合并）；同平台同金额同时刻（→ `candidate_same_platform`，不合并）；防误报反例（金额同但超窗 / 超窗内同商不同额 / 同商同额差 1 分 / 跨天同商户同额不同笔）。

### 3.4 订阅形态（对应 B4）

月付（≥3 期）/ 季付 / 年付 / 涨价序列（前后金额+日期）/ 周期中断（漏一期）/ 非周期相似金额干扰（防误报）。

## 四、真值台账（`data/truth/`）设计

- **逐条标注"输入与期望"，不存观测**：`{id, 输入内联引用, expect_*}`；**禁止出现 `observed` 类字段**（门禁机器化：真值库出现该字段即红）——观测必须由基准在运行时真喂引擎实算，否则"基准全绿"退化成"比对两份冻结答案"；
- 期望覆盖：导入三态（逐行期望 `ok/invalid/unknown`）、去重（应合并簇的成员集合与代表笔）、语义（逐行期望标签）、订阅（周期条目与涨价记录）；
- **评测口径单一实现源**：真值对账语义收成公共函数（bench 与测试共用），避免"基准说达标、测试说不过"；
- 真值库与样例**同源生成**（同一次运行、同一 RNG 流），故标注与数据必然一致；
- **覆盖度守门**：分母从生成器形态常量集反射，分子必须等于分母（防真值偏科）；"未知"注入存在性有专门断言。

## 五、冻结规则包（`data/rules/`）设计

- `manifest.json`：参数包（每个参数：值 / 单位 / 用户可配 flag / **来源标注"经验默认（非官方）"** / 说明）+ 基准门槛（达标率、误报上限等，**门槛是数据不是代码**）+ 规则包版本 + 覆盖度双登记 + 生成器版本；
- `keywords.json`：语义关键词表（规则条目：`{id, label, direction_condition, keywords[], priority, notes}`）；**一处定义、多处引用**；
- `aliases.json`：商户别名表（规范名 → 变体列表）+ 归并规则参数（后缀剥离白名单、全半角映射表）；
- 三者均为**冻结产物**（`gen_rules.py` 为唯一编辑面）：改词表 = 改生成器 + 整目录重生成 + `--check` 通过；
- **零参数字面量门禁**的数据来源：token 集从 `manifest.json` 的数值程序化生成（M3/M4 落地，见 `plan/03 §七`）。

## 六、数据台账与隐私

- `data/README.md` 追加**资产台账表**：逐文件登记 {路径、来源（程序化生成）、生成器 + seed、sha256、复核方式}；M1 收尾时全量回填；
- **假商户白名单**（`data/README.md §三`）是样例生成器的硬输入：白名单外的商户名**禁止**出现在任何样例/真值/演示里；生成器内置校验（出现白名单外名称即失败）；
- 假账号/卡号一律占位形态（如尾号 `****0000`）；**禁止**出现可识别为真实卡号的数字串（生成器内置正则黑名单自检）；
- 真实账单只在本机处理、永不入库（`.gitignore` `_private/` 机制）。

## 七、最小演示路径（每个里程碑可演示的公共示例）

```
tools/gen_samples.py  →  data/samples/* + data/truth/*
brc run data/samples/... --out output/      →  output/report.html（M2 起逐步成形）
brc bench --suite ...                        →  指标报告（M4）
```

- README 与演示命令只使用 `data/samples/` 下的合成样例；样例文件命名沿用 `data/README.md §三` 约定（`wechat-demo-*/alipay-demo-*/bank-demo-*`）；
- 大文件性能样例（数万行）**不入仓**，由生成器 `--big` 参数按需产出（M5 性能记录用）。
