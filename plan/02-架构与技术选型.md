# plan/02 架构与技术选型

仓库 `10-16-bill-reconciler`（多平台账单"真实支出"对账器）。v1（2026-10-15，M0 计划先行阶段落盘）。

> **文档关系**：需求与边界见 `plan/01-题目文档.md`；数据纪律（合成数据/真值台账/数值口径/隐私）的**唯一来源**是 `data/README.md`，本文档只做架构侧引用，不复制其口径。模块级细节见 `plan/03-模块详设.md`。

## 一、总体架构

五个功能模块对应五条子命令，串成一条**纯本地、纯确定性**的流水线；阶段之间只通过**文件**（JSON）交接，每一阶段可单独重跑，全部中间产物可审计：

```
用户通过官方自助功能导出的账单文件
（微信：解密后 CSV/XLSX；支付宝：CSV；银行：CSV/XLSX）
        │
        ▼  ① ingest（导入）
          编码白名单探测 → 表头广告行剥离 → 列名别名映射 → 行级解析（三态）
        │
        ▼  ledger.json（统一中间表示：records + issues + file_issues + meta）
        │
        ▼  ② normalize（商户名归一化：规则归并 + 逐条依据台账）
        │
        ▼  normalized.json（新增 normalized_counterparty + mapping evidence）
        │
        ▼  ③ dedup（金额＋时间窗口＋对手方三元组聚类；跨平台前提；逐簇依据）
        │
        ▼  dedup.json（候选簇 / 判定簇 / 代表笔 / 净流水视图）
        │
        ▼  ④ classify（冻结关键词表 + 收支方向组合 → 逐行语义标签 + 依据）
        │
        ▼  labels.json（消费 / 本人转账 / 退款 / AA回款 / 报销 / 未知）
        │
        ▼  ⑤ report（单一渲染源 → 人读 HTML + 机读 JSON 双轨）
        │
        ▼  report.html（单文件、零外链、断网可开） + report_data.json
```

数据资产供给（全部在 `data/`，唯一来源，见 `plan/04-数据计划.md`）：

- `data/rules/`（冻结规则包：参数包 + 语义关键词表 + 商户别名表）→ 被 ②③④⑤ 经**唯一访问点** `bill_reconciler/params.py` 读取；
- `data/samples/` + `data/truth/`（合成账单 + 真值台账）→ 被演示、测试与内置基准读取。

编排：`run` 子命令把 ①②③④⑤ 串成一条命令出结果（轻量状态机：节点 / 顺序 / 耗时记录；失败即停并报明阶段与原因）。

## 二、技术选型决策

| 项 | 选型 | 理由 |
|---|---|---|
| 语言与底线 | **Python ≥ 3.8，仅用标准库（核心零第三方运行时依赖）** | 账单处理无重依赖需求；零依赖 = 离线可跑 + 可复现优先 + 供应链面为零；底线 3.8 使本机 3.8/3.12 **双解释器通道**均可全量测试（见 §六），CI 矩阵同款。**待用户拍板确认（见 plan/06 §五 P1）** |
| CLI 框架 | `argparse`（标准库） | 子命令结构简单；无第三方依赖 |
| 金额处理 | **全链路 `decimal.Decimal`**（JSON 中以**字符串**存取；加载用 `parse_float=Decimal`） | 金额边界（分位差）不能被 float 尾差污染；"金额"是比较键的组成部分 |
| 中间表示 | JSON（UTF-8、LF 行尾、固定键序/固定排序、indent 固定） | 人可读、可 diff、可审计；无数据库依赖（个人账单规模不需要） |
| XLSX 读取 | **自写最小读取器**（`zipfile` + `xml.etree`；覆盖 sharedStrings / inlineStr / 数值与日期序列号） | 零第三方依赖纪律；只读不写，覆盖度显式声明，不支持特性 → 显式 `unsupported_container` 而非猜测 |
| XLSX 写入（仅合成样例用） | 自写最小 OOXML writer（`ZIP_STORED` + 固定 `create_system`/`date_time` 常量） | 合成样例是**字节冻结资产**：跨平台重生成位级一致（生成期纪律见 plan/04） |
| HTML 报告 | **自写最小渲染器**（零模板引擎、零 CDN、零外链、内联 CSS；首期零 JS） | "单文件零依赖"是卖点；且渲染是确定性的一部分（同输入同字节） |
| 测试框架 | `pytest`（仅 dev 依赖） | 生态标准；本机双通道已具备 |
| 基准 | 内置 `bench` 子命令 + 探活测试；门槛随规则包 manifest 下发（数据非代码） | 见 `plan/03 §十一` 与 `plan/05` M4 |
| LLM | **不使用**（全链路零 LLM） | 决策记录见 `plan/00 §二`：纯确定性规则 + 结构化输入，无解析兜底需求；结论 100% 可复现 |
| 网络 | **零网络调用**（无 socket / 无遥测 / 无账号） | 隐私红线（`data/README.md §五`）；M4 以静态门禁 + 运行期断言固化 |
| 分发形态 | 源码仓库（git clone）/ `pip install -e .`（editable）/ Release 源码 zip | 不做 PyPI 首发、不做 exe（首期非目标）；见 §五 |

## 四、关键架构决策与取舍

### 4.1 布局：包平铺在仓库根（`bill_reconciler/`）

- **决策**：不采用 `src/` 布局，`bill_reconciler/` 直接放仓库根。
- **理由**：产品要求"**免安装（有 Python 即可）**"（`plan/00` M5 DoD）——平铺布局下 `git clone` / 解压发布 zip 后**在仓库根直接 `python -m bill_reconciler` 即可跑**（CWD 在 `sys.path` 上），不需要先建 venv、先 pip 安装；`src/` 布局做不到这一点。
- **代价与处置**：平铺布局存在"CWD 恰好让包可导入、掩盖未安装问题"的风险（系列方法论有实录教训）。处置 = **两条通路分别有测试与冒烟**：①仓库根 `python -m bill_reconciler`（免安装通路）；②经 `pip install -e .` 后的**console script**（`bill-reconciler` / `brc`），且在**任意工作目录**下冒烟（安装通路）。CI 与干净环境验证都跑这两条。

### 4.2 安装与分发形态

| 通路 | 形态 | 说明 |
|---|---|---|
| A（主推） | 源码仓库 / Release 源码 zip → 仓库根 `python -m bill_reconciler` | 零安装；数据目录经 §4.3 解析到仓库内 `data/` |
| B | `pip install -e ".[dev]"` → `bill-reconciler` / `brc` / `python -m bill_reconciler` | 开发与测试通路；README 快速开始使用该通路 |
| C（非目标） | PyPI 发布、二进制 exe | 首期不做（01 形态决策：有 Python 即用）；非 editable 的 `pip install .` 因 `data/` 不随包（站点包安装后找不到数据目录）列为**已知限制**，README「已知问题」节写明 |

console script 双名：`bill-reconciler`（全名）+ `brc`（短别名，系列习惯）。

### 4.3 数据目录解析（`datadir.py`，唯一入口）

解析顺序（写死、有测试）：

1. **环境变量 `BILL_RECONCILER_DATA`**：显式指定 → 必须有效（含 `README.md`），无效即报错**不回落**（显式意图不静默）；
2. **从当前工作目录向上逐级探查**：找含 `data/README.md` 的目录（覆盖仓库根直跑、editable 安装在仓库内使用、发布 zip 解压场景）。

> **M0 实测勘误**：最初设计含"从包文件位置向上探查"一支——实跑发现它在**仓库子目录**里会经包位置误命中仓库根 `data/`（隔离目录测试失败暴露），已删除该支：站点包内的路径"装到哪算哪"，数据目录应跟随用户位置或显式声明。editable 安装场景由"CWD 向上探查"覆盖（仓库内使用时 CWD 必在仓库内）。

全部失败 → `EnvError`（退出码 3），提示设置环境变量或在仓库根运行。任何功能代码**不得**自行拼数据路径，一律经此入口。

### 4.4 确定性纪律（可直接测试的性质）

- **无随机**：生成器禁 `random` 模块，用自研 splitmix64（固定 seed）；引擎侧不引入任何随机。
- **无时钟**：生成与解析**不读系统时钟**；所有产物（含报告）**不含生成时间戳**——"同输入 → 同产物字节"才成立（时间来源只允许来自账单数据本身）。
- **无 `set` 迭代序依赖**：一切排序显式声明排序键（如记录按 `(时间, 平台, 来源行号, id)`；簇按代表笔排序键）。
- **金额全链路 Decimal**、**JSON 字符串化**（`"12.34"`）。
- **产物字节确定性**：HTML / JSON 输出同输入同字节；冻结数据资产由生成器 `--check` 位级守门（plan/04）。
- **行尾**：源码与产物一律 LF；`.gitattributes` 对**冻结快照类**文件标 `-text`（防 EOL 改写字节）。

### 4.5 错误处理与退出码语义（锁进 CLI 测试）

统一的退出码契约（所有子命令一致，后续实现不得漂移）：

| 退出码 | 语义 | 典型情形 |
|---|---|---|
| **0** | 完成且无未决事项 | 全部行可用于核算；基准达标；自检通过 |
| **1** | **完成但检出需人工处理的问题**（清单必打印，不静默） | 行级异常清单非空（如金额非数值的个别行）；bench 未达标；selftest FAIL |
| **2** | **用法或输入不可用** | 未知子命令 / 缺参 / 文件不存在 / 整份文件形态不可用（编码探测失败、表头定位失败、空文件等） |
| **3** | **环境不可用** | `data/` 目录解析失败；可选依赖缺失（首期核心零依赖，此分支主要为数据目录问题保留语义） |

- 领域异常一律继承 `BillReconcilerError(ValueError)`，CLI 只捕获该基类并映射退出码；真实内部缺陷**不得**被 `except Exception` 吞掉（任其带栈报错，便于定位）。
- 违反契约的两个反面（据系列方法论实录写成守门）：把**行级问题**报成 exit 2（用户误以为整份文件都不能用）、把**形态问题**降级成 exit 1（用户误以为改几行就好）——两者都要有失败路径测试。
- **M0 骨架期约定**：未实现命令（import/normalize/dedup/classify/report/run/bench）打印"尚未实现（计划于 Mx）"并返回 **2**；各命令在对应里程碑实现后，测试期望按上表翻转为最终语义。

### 4.6 隐私与"零上传"的架构落点

1. 代码层：不 import 任何网络库（`socket`/`urllib`/`http`/`ssl` 等；M4 加 AST/源码静态门禁）；
2. 运行期：流水线无任何外连行为（M4 加"运行期无外连"断言测试）；
3. 数据层：真实账单永不入库（`.gitignore` 的 `_private/` 机制 + `data/README.md §五`）；演示与基准一律合成数据；
4. 合规层：不触碰平台加密数据库、不做密码破解（边界见 `plan/01 §六`）。

### 4.7 性能与规模

- 目标规模：单份账单数千行、合并后**万行级**；全流水线在普通笔记本上**数秒内**完成（M5 记录实测值）；
- 性能不靠并发/数据库解决；若后续大规模场景需要，列为扩展项（首期不做）。

### 4.8 备选方案取舍记录

| 备选 | 不采用原因 |
|---|---|
| pandas / openpyxl | 破坏"零第三方依赖"与字节确定性目标；账单解析所需能力用标准库可覆盖（XLSX 读取面自写、覆盖度显式声明） |
| SQLite 作中间库 | 个人账单规模用不着；JSON 可读可 diff 可审计，符合"账单是审计凭证"定位 |
| LLM 辅助解析 | 无"非结构化兜底"需求；确定性优先（`plan/00 §二` 已录） |
| 桌面 GUI / exe | `plan/01` 形态决策：CLI + 本地 HTML 即交付形态；GUI 与"数据不出机"卖点无关且成本高 |
| 云端 / 账号体系 | 隐私红线；纯本地是卖点 |
| FastAPI 本地 Web 面板 | 超出 01 范围；HTML 单文件报告已满足"可视化"需求，且 0 外链更易达成 |
