# plan/05 里程碑

仓库 `10-16-bill-reconciler`（多平台账单"真实支出"对账器）。v1（2026-10-15，M0 计划先行阶段落盘）。

> **里程碑纪律（全程硬约束）**：
> 1. **一个里程碑 = 一个对话**；每个里程碑出口判据**全部达成并验证**后，必须**在本对话内**写完下一棒的 `plan/HANDOFF-M<next>.md` 才允许收尾（六节齐：进度+证据 / 待办 / 既定口径 K 清单 / 本机环境坑 / 命令速查 / 启动提示词）；
> 2. 收尾顺序固定：**DoD 验证 → plan/00·05·06 状态回写 → 写 HANDOFF → commit →（有远端则 push 等 CI 绿）**；
> 3. 里程碑**阻塞在用户动作**时：更新当前 HANDOFF 待办区 + 续接指针，不写虚构的下一棒；
> 4. **诚实口径**：未推送 = 未跑 CI，DoD 一律写"本地等价校验（未接远端，CI 待首推验证）"，首推后据实补记。
>
> **每周可演示**：每个里程碑都必须留下一条**可当场跑通的演示命令**（下表"可演示"列）。

## M1 数据先行（下一棒）

**目标**：把 `plan/04` 的资产方案落成**冻结数据资产 + 生成器 + 守门**。这是全项目"真值可复现"的地基。

**交付物**：

1. `tools/gen_samples.py`：产出 `data/samples/*`（三平台、形态矩阵见 plan/04 §三）与 `data/truth/*`（同源真值台账）；
2. `tools/gen_rules.py`：产出 `data/rules/{manifest,keywords,aliases}.json`；
3. `tools/check_frozen.py`：全量 `--check` 入口；
4. `data/README.md` 资产台账逐文件回填（sha256、生成器、seed）；
5. 测试：生成器 `--check` 位级一致（双解释器）、覆盖度双登记断言、真值库"无 observed 字段"门禁、白名单/卡号自检、XLSX 重生成字节一致。

**DoD 要点**：

- [ ] 生成器确定性：无 `random`/`set` 无序/时钟；两次运行逐字节一致（含 XLSX：`ZIP_STORED`+固定元数据）
- [ ] 形态矩阵全部注入（导入 7 类 / 语义 6 类含未知 / 去重 6 类 / 订阅 6 类），覆盖度双登记（总数/采样数/清单）
- [ ] 真值库只存输入与期望；对账语义单一实现源
- [ ] `.gitattributes` `-text` 生效；克隆后 sha256 与台账一致
- [ ] `selftest` 的数据资产检查从 PENDING 翻转为 PASS（测试同步翻转，注明期望变更）
- [ ] HANDOFF-M2 落盘

**可演示**：`py tools/check_frozen.py` → 全绿；`python -m bill_reconciler selftest` → 数据资产 PASS。

**依赖的拍板项**：建仓与首推时点（plan/06 §五 P2）——若拍板"M1 收尾建仓"，M1 收尾多一步 push + CI 首跑。
